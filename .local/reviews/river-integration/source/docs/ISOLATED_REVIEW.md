Incluye worker/core/editorial/ruta/panel de Instagram, imagen y build de assets, esquema y SQL aditivo sin aplicar, timeout de subida, política pura de runtime y pruebas offline. Se conservaron íntegros `session-device.ts`, auth, user-agent, sesiones y `pointerdown` del commit base.

`ISOLATED_REVIEW=true` bloquea el entrypoint antes de importar Express/DB, además de deshabilitar entrega automática. `AUTOMATION_ENABLED=false` impide scheduler, plantel, webhooks, cola, Make y worker. No protege a quien ejecute otro entrypoint o importe módulos a mano. El worker **solo lee catálogos** para comprobar esquema, trigger habilitado y función; si faltan, no arranca. Nunca hace DDL ni backfill al inicio.

Operador: elegir explícitamente `INSTAGRAM_DELIVERY_MODE=disabled|make|direct`. En revisión el modo efectivo es siempre `disabled`; fuera, la omisión conserva `make` por compatibilidad, pero requiere decisión operativa antes de despliegue. `direct` requiere `INSTAGRAM_ENABLED=true` y parámetros válidos de la cuenta River; no se activa para Selección. Las dos salidas Make/direct son excluyentes. El creativo opcional por Telegram (`EDITORIAL_TELEGRAM_ENABLED=true`) es adicional a las notificaciones principales.
